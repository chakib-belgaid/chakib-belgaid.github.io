Selected work

Two systems, each documented with architecture, trade-offs, current status and verifiable proof.

01

Whispbook

A self-hosted React and FastAPI audiobook studio, paired with research tooling for schema-constrained speaker attribution and local LoRA evaluation.

Role
Chakib owns the product workflow and backend/frontend implementation, and built the separate attribution research path for controlled context, structured tool outputs, local LoRA adapters and evaluation reports.
Architecture
The product path converts local documents into editable chapters, snapshots book state and TTS settings, then generates chapter audio, subtitles and an M4B package. The research path prepares speaker candidates and surrounding evidence for schema-constrained attribution and evaluates local adapters separately.
Technology
React, TypeScript, FastAPI, Docker, Kokoro

02

Wattch

A Rust daemon and CLI boundary for local energy and system-telemetry capture, designed around explicit evidence classes, deterministic validation and replayable traces.

Role
Chakib designed the daemon/client boundary, protocol and validation model, built the RAPL prototype and evolved it into a backend-independent trace-first foundation with deterministic test scenarios.
Architecture
A privileged acquisition daemon reads raw counters and serves a strict local socket protocol. Unprivileged CLI and Python clients capture source descriptors and sample batches into replayable run artifacts; interpretation stays offline.
Technology
Rust, Linux, RAPL, Unix sockets, Protobuf
